# 都江堰一日游：雨天 / 拥堵 / 疲劳现场决策树

- Canonical task: `TASK_TRAVEL_FIELD_RAIN_CROWD_01`
- Agent: `AG_TRAVEL_FIELD_BOOK`
- Research snapshot: **2026-09-03**
- Declared goal: 为雨天、桥梁排队、疲劳、晚到、用餐延误和返程保护建立可执行 if-then 规则，同时尽量保留鱼嘴、飞沙堰、宝瓶口三个核心水利节点。
- Safety boundary: **任何官方闭园、暂停进入危险区域、雷暴/强降雨/山洪或地质灾害风险提示，都优先于行程完整度。** 本文件不提供绕过管控的办法。

## 0. 一条总原则

遇到任何异常，不要先问“还能不能把所有点打完”，而是按以下顺序保护：

**人身安全 > 返程可控 > 鱼嘴 / 飞沙堰 / 宝瓶口核心体验 > 正式坐餐与恢复 > 安澜索桥 / 二王庙 / 秦堰楼 / 单一拍照点 / 夜景等可选项。**

这条优先级与现有路线研究一致：都江堰第一次来最有价值的是理解三大水利节点的系统关系，而不是堆满景点；游客反馈也显示单一拍照点排队、坡度与步行量会明显消耗体验。

# 1. 总入口决策树

```text
到达都江堰中央游览区
│
├─ A. 官方发布闭园 / 暂停入园 / 危险区域管控？
│   ├─ 是 → 不排队硬闯、不绕行管控 → 转安全室内/古城坐餐/返程方案
│   │        → 持续以官方公告、现场人员和 028-96526 为准
│   └─ 否 → 进入 B
│
├─ B. 有强降雨、雷暴、山洪/地灾预警或现场水势/路况明显异常？
│   ├─ 是 → 执行“强天气树”（第 2 节）
│   └─ 否 → 进入 C
│
├─ C. 只是小雨/间歇雨？
│   ├─ 是 → 优先低风险、较平缓核心段；桥梁/陡坡按现场情况决定
│   └─ 否 → 进入 D
│
├─ D. 官方大客流预警、售票收紧或入口明显拥堵？
│   ├─ 是 → 执行“拥堵树”（第 3 节）
│   └─ 否 → 正常核心路线
│
└─ E. 任何时刻触发疲劳 / 晚到 / 用餐延误 / 返程警戒线？
    └─ 是 → 分别执行第 4–7 节的削减规则
```

# 2. 雨天与强天气决策树

## 2.1 普通小雨 / 间歇雨

**IF** 没有官方风险预警、没有闭园/限行，现场只是普通小雨，路面状况正常，  
**THEN** 可以继续游览，但把路线改成“**核心优先、坡桥后置**”：

1. 先保留鱼嘴、飞沙堰、宝瓶口的核心解释和观察；
2. 经过湿滑石阶、木桥或坡道时降低速度，不为了追赶计划抢行；
3. 安澜索桥、二王庙/秦堰楼等带桥梁、坡度或额外高度成本的节点改为现场判断；
4. “厕所 + 遮雨 + 坐下”合并成一个恢复节点；
5. 若衣物已经明显湿透或体温舒适度下降，立即转游客服务点或正式坐餐，不把“再走一个点”当优先项。

**核心逻辑：** 小雨并不自动取消水利核心，但会提高坡、桥、重复步行和长时间站立的成本。

## 2.2 强降雨 / 雷暴 / 山洪或地灾风险

**IF** 出现以下任一信号：

- 官方景区发布临时闭园、暂停入园或危险区域限制；
- 当地气象、应急、自然资源部门发布与都江堰相关的强降雨、山洪、地质灾害高风险提示；
- 现场工作人员要求撤离/调整游线；
- 雷电、持续强降雨、水位变化或边坡/道路状况让现场安全条件明显恶化；

**THEN：**

- **不进入、不抢最后一段、不自行寻找“还能走的小路”。**
- 已在景区内时，服从现场广播和工作人员疏导，向开放的安全服务区/出口转移。
- 不在河边、桥面、临水拍照点或坡脚等待天气“马上变好”。
- 将当日目标降级为安全室内休息、古城正式坐餐、车站返程或改日再访。

### 为什么必须这么严格

2025-08-29，青城山—都江堰景区因地质灾害气象风险实行临时闭园，公告明确表示预警解除后还要经过综合安全评估才恢复开放。这说明“雨停了”并不等于“景区立即安全开放”。四川省文旅部门也多次提示强降雨可引发山洪、地质灾害等次生风险，要求游客关注预警并避开高风险区域。

因此，**任何官方风险管控都直接终止本决策树中的“保核心节点”目标。安全优先。**

# 3. 拥堵与桥梁排队决策树

## 3.1 入口大客流

2026 年春节和清明期间，都江堰景区多次发布大客流预警：日最大承载量公开为 4.8 万人次；达到预警人数后会停止 OTA、旅行社及部分线上渠道销售，客流进一步升高时可启动暂停入园措施。这个机制证明“有票/到门口”并不意味着任何时刻都能无等待进入。

**IF** 官方已经发布大客流预警，但仍允许按预约时段进入，  
**THEN：**

- 不在入口外临时增加拍照/购物；
- 入园后直接向核心水利体验推进；
- 将古城闲逛、甜品、购物等弹性项目放到景区之后；
- 把安澜索桥和小型热门观景台视为可删节点。

**IF** 景区已经启动“暂停入园”，  
**THEN：**

- 不在门口持续耗时赌恢复；
- 立即切换到“古城/南桥公共区域 + 正式坐餐 + 休息”缓冲；
- 同时关注官方售票/入园状态；
- 若恢复时间开始侵蚀返程安全窗口，则放弃当日完整景区路线，不以“已经到了”为理由硬等。

## 3.2 安澜索桥或单一拍照点排队

游客反馈已出现小型观景/拍照平台排队现象。桥梁这类瓶颈节点在大客流时也天然更容易形成速度下降。

**IF** 安澜索桥/某拍照点出现明显长队，且它不是理解水利系统所必需，  
**THEN** 直接使用下面的判断：

```text
是否已看完鱼嘴、飞沙堰、宝瓶口？
├─ 否 → 跳过队伍，先保核心节点
└─ 是 → 体力和返程时间都宽裕？
        ├─ 否 → 跳过
        └─ 是 → 队伍仍值得等吗？
                ├─ 否 → 跳过
                └─ 是 → 可自愿等待，但设置明确撤退点
```

**不把“排了十分钟所以必须继续排”作为理由。** 已投入时间是沉没成本。

## 3.3 观光车排队

从设施审计继承：当前 OTA 参考观光车主要覆盖碑亭—鱼嘴，参考价单程 10 元、往返 15 元，但价格、站点和运营状态均需现场核对。

**IF** 乘车目的是省体力，但排队时间已经让人持续站立、烦躁，或明显不比步行节省体验成本，  
**THEN** 不因“车更轻松”而机械排队：

- 体力尚可 → 改步行；
- 体力不足 → 先坐下恢复，再向工作人员确认下一班/其他站点；
- 已接近返程警戒线 → 不再等待观光车，按最稳定的离园方式退出。

# 4. 疲劳决策树

将疲劳分三级，不要求精确医学量化，而用可观察状态判断。

## 4.1 轻度疲劳

表现：只是想坐一下、步速略下降、仍能正常交流。

**THEN：** 3–10 分钟短休 + 补水；保持核心路线，不急着删点。

## 4.2 中度疲劳

表现：明显不想继续上坡、开始频繁找座位、交流质量下降、脚腿酸胀持续。

**THEN：**

1. 先坐下 10–20 分钟；
2. 删除安澜索桥排队、二王庙/秦堰楼额外爬升、重复拍照；
3. 若有合适观光车且排队合理，可单程利用；
4. 保留三个核心水利节点后尽快转古城正式坐餐。

## 4.3 重度疲劳 / 明显不适

表现：继续走需要“硬撑”、明显疼痛、头晕、恶心、发冷/过热或其他身体不适。

**THEN：** 终止景点完整度目标，直接寻求休息、工作人员帮助或医疗支持；必要时拨打景区咨询/救援电话 **028-96526** 或公共急救电话。

**规则：** 1.5 万步是规划参考，不是任务指标，更不是必须完成的配额。

# 5. 晚到决策树

“晚到”不是某一个固定时刻，而是指：**剩余开放时间已经不足以舒适完成原路线 + 正式坐餐 + 返程保护。**

**IF** 到达晚，但仍能从容完成水利核心，  
**THEN** 直接采用压缩版：

**入口 → 三大水利核心 → 视体力决定是否加安澜索桥 → 出景区 → 正式坐餐/古城 → 返程。**

**IF** 到达更晚，核心 + 返程之间已经开始冲突，  
**THEN**：

- 删除二王庙/秦堰楼等爬升项；
- 删除单一拍照队伍；
- 删除“必须等夜景”的要求；
- 必要时利用观光车减少低信息密度步行；
- 仍不足时，只保留最能理解整体工程关系的核心段，不把离园时间推到不可控。

**IF** 已到现场但官方停止售票/暂停入园，且恢复时间未知，  
**THEN** 不把一日行程变成门口等待游戏；先切换古城/吃饭，并设置返程硬截止。

# 6. 用餐延误决策树

正式坐餐是恢复节点，不是必须去某一家店的“打卡任务”。

**IF** 目标餐厅排队轻微，且不影响核心参观/返程，  
**THEN** 正常等位。

**IF** 等位已经明显侵蚀后续路线，  
**THEN** 按优先级处理：

1. **核心景区尚未完成** → 不为了名店排长队，换附近可坐下的合格餐厅或先轻补给；
2. **核心已完成但人很累** → “能尽快坐下”优先于餐厅名气；
3. **临近返程保护线** → 选能快速完成的坐餐/轻餐，不再跨区追店；
4. 若一顿饭整体向后推迟，则同步删除一个低优先级景点，而不是把所有后续项目一起压缩。

**禁止的错误补偿：** 因午餐晚了就取消所有休息、加速走景区。这会把一个小延误放大成疲劳和返程风险。

# 7. 返程保护决策树

返程不能只看“地图显示去车站要多少分钟”。还必须覆盖：离开当前节点、拥堵/找车、进站、安检/检票、找站台，以及动态交通波动。

## 7.1 建立两个时间点

最终路线在出发前刷新车次后，应生成两个相对时间点：

- **R1：返程收口点** = 计划列车发车时间 −（当前节点到车站的保守交通时间 + 进站缓冲 + 额外异常余量）。
- **R2：必须离开点** = 再晚就不允许新增任何景点、排队、跨区餐厅或夜景等待的时间。

这里不固化某一个私人车次或精确日期；最终 T-minus-1 刷新时再填写。

## 7.2 现场规则

**IF** 尚未到 R1，  
**THEN** 可按正常路线活动。

**IF** 到达 R1，  
**THEN**：

- 停止新增景点；
- 结束购物/拍照队伍；
- 只保留已经开始的用餐或必要厕所；
- 开始向选定车站收口。

**IF** 到达 R2 或出现交通异常，  
**THEN** 直接去车站，不再等待夜景、桥梁、观光车或热门餐厅。

**IF** 原定车站/车次出现问题，  
**THEN** 按项目的返程铁路矩阵比较离堆公园站与都江堰站的当前可用候选，不把两个站混为一处，也不凭旧时刻表猜车。

# 8. 五个常见组合场景

## 场景 A：小雨 + 人不多

**决策：** 核心水利正常走，安澜索桥/坡道现场看湿滑程度；增加一次室内/有遮蔽休息；古城坐餐作为长恢复。

## 场景 B：小雨 + 大客流

**决策：** 只要官方允许入园，就尽快进入核心；跳过拍照排队；桥梁若拥堵直接删；必要时用观光车降低重复步行。若官方暂停入园，则切古城/餐饮等待，不堵门口。

## 场景 C：强降雨 / 地灾预警

**决策：** 安全管控覆盖一切路线设计。若闭园/限制区域，立即放弃景区完整度目标，不自行绕行。

## 场景 D：晴天但已经很累

**决策：** 删除坡度与排队项；保核心；尽早正式坐餐；不因为天气好就强行把“能去”理解成“应该去”。

## 场景 E：到达晚 + 餐厅又排队

**决策：** 先保三大水利核心；用餐改为附近更快可坐下的方案；安澜索桥/山坡节点和夜景均降级；按 R1/R2 收口返程。

# 9. 需要现场复核的动态信号

最终手机指南在临行刷新时，至少重新确认：

1. 景区当天开放/闭园/限流公告；
2. 是否出现大客流预警或暂停入园；
3. 成都—都江堰区域天气、雷暴、强降雨、山洪/地灾风险；
4. 观光车当天线路、价格、停运/排队；
5. 选定返程车次及离堆公园站/都江堰站备选；
6. 正式餐厅当前营业与等位；
7. 028-96526 官方热线是否仍为当前服务入口。

## 最终结论

真正稳健的雨天/拥堵方案不是准备另一条同样长的路线，而是准备一组**可及时舍弃的项目**。只要安全条件允许，先保护鱼嘴—飞沙堰—宝瓶口的核心理解；一旦天气风险、官方管控、严重疲劳或返程警戒线触发，就让“少看一点”成为预先设计好的正确动作，而不是现场失败。
