## Principle

This project uses a **one-confirmation operator policy** because the scope is modest. The first meaningful requirements/result checkpoint has already been shown to the operator and approved. Routine execution therefore should continue without asking for two additional warmup confirmations once the project override is wired into the canonical runner.

The repository-wide UOS quality gate remains the canonical safety mechanism; this project-level operator policy governs how this project is presented and reviewed. Sampling, high-risk review, map verification, privacy review and final audit still apply.

## Recommended agent topology

Use 5 active agents in steady state, with an optional 6th reviewer.

1. AG_TRAVEL_TRANSIT_MAP
   - geography, station choice, transit, current POI/access validation, map fact sheets
   - owns: GEO_TRANSIT, ROUTE_PATTERNS, map-base validation inputs

2. AG_TRAVEL_CULTURE_REVIEWS
   - history/culture, recent visitor reviews, recent news/operations
   - owns: HISTORY_CULTURE, REVIEWS, NEWS

3. AG_TRAVEL_FOOD_DATA
   - food, visitor profile, seasonal flow, cost model
   - owns: FOOD, VISITOR_PROFILE, SEASONAL_FLOW, COST_MODEL when dependencies are satisfied

4. AG_TRAVEL_PRIVATE_PLAN
   - encrypted interaction design, gifting, photo/camera handling, pre-trip communication
   - requires privacy audit and private key supplied out-of-repository
   - never writes private plaintext to canonical artifacts

5. AG_TRAVEL_FIELD_BOOK
   - location dossiers, AMap time matrix, facilities, rain/crowd decision tree, search-index inputs
   - consumes only public project context

6. AG_TRAVEL_REVIEW (optional but recommended)
   - privacy/factual/map/budget/source review
   - must not author and approve the same critical artifact when an independent reviewer is available

## Review policy for this project

- Routine operator confirmations required: 1.
- Status: SATISFIED by the initial requirements/result confirmation.
- No second or third routine confirmation should be requested after the execution-layer override is fixed.
- Later operator interruption is only needed when:
  - a high-risk/private artifact needs explicit review;
  - a generated map cannot be reconciled with validated geography;
  - a material budget/transport assumption changes;
  - the final audit finds a blocking issue;
  - the operator voluntarily changes requirements.

## Parallel waves

### Recovery wave — first priority
- fix project warmup override integration;
- publish the 26 book-depth task slots into canonical catalog;
- reconcile Work Market;
- verify multiple compatible READY tasks exist.

### Wave 1 — Parallel research
Can run simultaneously:
- geography / transit
- history / culture
- reviews
- food
- route patterns
- recent news
- visitor profile
- seasonal flow
- location dossiers / field operations after expansion publication

### Wave 2 — Dependent analysis + private planning
- cost model after geography + food
- interaction design after privacy audit + culture + route patterns
- gift design after privacy audit + food + culture

These can run in parallel with each other once dependencies are satisfied.

### Wave 3 — Synthesis
- five distinct schemes

Single-owner synthesis is preferred to keep the five plans coherent, while reviewers may inspect in parallel.

### Wave 4 — Map generation loop
For each scheme independently:
1. validated fact sheet
2. dedicated image-generation prompt
3. independent route image
4. generation receipt
5. visual/factual verification
6. reject/regenerate when wrong

Schemes A-E may be generated by separate agents in parallel if they all consume the same validated map base and validation policy.

### Wave 5 — Deliverables
- five full private guide PDFs may be assembled in parallel
- research digest can run in parallel
- pre-trip communication guide can run in parallel

### Wave 6 — Dynamic refresh + final audit
- last-minute transport/weather/opening/crowd refresh
- final independent factual/privacy/budget/map audit

## Concurrency recommendation

Preferred steady-state concurrency: 4-5 agents.

Do not exceed 6 concurrent agents for this project. More agents create unnecessary synchronization and review overhead.

## Ownership and safety

All agents must use canonical UOS Claim / Lease / Fencing when operating through the UOS runner. Work Market discovery is not ownership.

Private-context agents must receive the encryption key out-of-repository and may only decrypt transiently. Public research agents do not need the key.

Map-generation agents are not permitted to invent geography. Image generation is only a rendering stage; validated facts remain authoritative.

## Task-count constraint

Multi-agent execution does not change the project hard limit of <= 50 canonical tasks. The current canonical catalog has 24 tasks; 26 additional slots are planned for book-depth parallel research. Parallelism changes ownership and scheduling, not task inflation.
