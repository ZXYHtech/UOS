# Inventory Pro 改进、测试与上线计划

更新：2026-09-14。以下为工程估算，不是上线承诺；以验收门是否通过为准。

## 事实基线

- 实现来自旧库存仓库 E00 提交 `0e08704`，保留完整祖先历史；新架构代码此后仅写 `ZXYHtech/inventory-Pro`。
- 规划来自 UOS `impl/inventory-evolution-v1` 的 `b7557ab`，采用模块化单体 + 关系数据库 + 持久 worker/outbox；默认保留 SQLite。
- E00 有实际代码，仍待修复与验收；E01–E15 是设计与执行包，不是已实现模块。UOS 原目录只有 22 个顶层任务，不能把两百多份设计产物计为完成的业务功能。
- 本机实测：迁移、完整性、清单复制、认证、核心业务、识别与仓库效率通过；恢复和定时备份失败。快照测试存在 macOS 路径规范化问题，换规范路径后通过。目标 Linux 尚未验收。
- 旧系统的淘宝采集、移动端后续修复与合同功能来自不同分支，Pro 未自然包含；按业务清单挑选整合，不整仓替换现网。

## 改进优先级

1. **P0 仓库与运行隔离**：新开发只进 Pro；UOS 旧上下文重新读隔离规范；旧 PR #3 不再是合并入口。独立端口、数据、服务、账号与测试地址。
2. **P0 E00 验收闭环**：修复 `recovery_verifier.py` 的 SQLite 恢复失败；兼容规范路径；新增 Pro 独立部署入口并统一安全检查；备份同时约束数量、天数与异机空间。
3. **P0 功能基线**：列出必须保留的已上线能力，逐项确认来源提交与回归，不将旧主干误当现网完整功能集。
4. **P1 E01 + E11 早期**：服务端权限、请求上下文、业务操作幂等、持久任务/租约、outbox、关联审计；价格底线授权独立。
5. **P1 E02**：库存身份/单位、不可变流水、余额投影、预留/ATP；影子写入和全量对账；物理发货只扣减一次。核实采购分批收货是否重复分摊整单运费。
6. **P1 E03**：库位身份与布局分离、共享扫码解析、暂存/上架/拣货/盘点状态、手机高频入口一致。
7. **P2 E04–E12**：以真实研发生产业务试点推进，避免一次上齐所有 ERP 模块。
8. **P3 E13–E15**：规则和 AI 只调用受控命令；PostgreSQL 根据锁等待、性能、恢复时间等实测指标决定。

## 测试计划大纲

### 每个提交 / PR
- 语法、类型/接口契约及确定性临时数据库回归；任何必测缺失即失败。
- 角色/仓库/对象权限，错误响应与审计；无越权下载与修改。
- 版本化迁移连续、重复执行无变化、失败回滚、旧数据不被伪造补齐。

### 执行与库存核心
- 同业务请求重复提交、两个并发操作者、超时后重试、进程崩溃恢复、过期 worker 隔离。
- 下单→预留→发货→取消/撤回；调出→在途→部分收货→差异补收；采购分批收货；盘点观察→审批调整。
- 守恒、余额重建、负库存边界、数量单位转换与价格/成本快照；逐单/逐仓新旧对账。
- 人工修改商品保护、淘宝关闭/未发货/状态未知、单笔失败重采、迟到结果补传；移动端对应入口。

### 测试服务器
- 独立目录/端口/数据库/服务，证明不会读写旧系统；新进程不应带旧服务器凭据。
- 升级前快照、备份恢复、异机校验、定时备份与数量清理；权限/磁盘不足/备份损坏/停电中断。
- 更新失败和健康检查失败后的安全停止，人工恢复旧测试版本；测量实际恢复时间。
- 按脱敏代表性订单量和并发做压力、长任务、弱网、服务重启测试；记录环境/提交/命令/结果。

### 上线门
- 必测全通过；无未解决的库存一致性、权限、丢数据级问题。
- 核心功能清单逐项保留；数据导入只使用另行授权的副本并完成对账。
- 业务操作员验收手机与 PC；试用观察 1–2 周。
- 明确备份目标、RPO/RTO、维护窗口、回退责任；生产切换需要新的明确授权。
